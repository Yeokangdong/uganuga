[팀 공통 규칙 — 토큰 절약]
- 지시받은 파일만 만들고 기존 결과물은 재생성하지 않는다. 검증용 스크립트·보고서·메모를 따로 만들지 않으며 저장은 존재·크기만 확인한다.
- 필요한 문서·항목만 읽고 참고 이미지는 필수 1~2장만 사용한다. 질문 없이 끝까지 진행하고 설명은 짧게, 완료 시 결과 파일 목록 한 줄만 출력한다.
- 스프라이트는 칸마다 사방 15% 이상 여백, 칸 밖·옆 칸 침범 금지, 실제 투명 배경을 지킨다.
- 긴 소스·로그는 검색 후 필요한 범위만 읽고, 이미 읽은 내용·전체 목록을 반복 출력하지 않는다.
- 빌드는 완료 확인에 1회 실행하고 이후 변경·실패가 있을 때만 재실행한다. 이미지 생성·열기는 필요한 대상만 처리한다.
- 정기 토큰 점검은 매 10번째 작업마다 1회만: 로그 끝 tokens used 상위 10개와 원인 확인·규칙 보완(이번은 141번 특별 점검).


306 테스트 — 예전 엔진 키 입력 완주 검사기 (게임 코드 수정 금지)

목적: 298 계획 12번(최종 QA)과 매 작업 검수에 쓸 "키 입력만으로 판 진행" 자동 검사기를 미리 만든다.
참고(수치·방식만): backup/phaser-main 브랜치의 src-phaser\complete.mjs. 코드 복사 말고 예전 엔진(src\)에 맞게 새로 작성.

할 일
1. 신규 파일만: tools\playthrough.mjs (headless Chrome/Playwright, 창 띄우지 말 것). npm run dev 를 포트 5306으로 잠깐 띄워 사용하고 끝나면 종료.
2. ?stage=N 으로 진입해 키 입력(← → ↑ Space)만으로 진행: 먹이 수집 → FOOD 60 → 보스 문 → 보스 처치 → 다음 판. 막히면 판·좌표·시간·스크린샷을 기록.
3. 사용법: node tools\playthrough.mjs --stages 1-15 --out shots\playthrough
4. 지금 상태로 1~3판만 시험 실행하고 결과를 표로(판 | 완주 O/X | 막힌 곳 | 걸린 시간).
