[팀 공통 규칙 — 토큰 절약]
- 지시받은 파일만 만들고 기존 결과물은 재생성하지 않는다. 검증용 스크립트·보고서·메모를 따로 만들지 않으며 저장은 존재·크기만 확인한다.
- 필요한 문서·항목만 읽고 참고 이미지는 필수 1~2장만 사용한다. 질문 없이 끝까지 진행하고 설명은 짧게, 완료 시 결과 파일 목록 한 줄만 출력한다.
- 스프라이트는 칸마다 사방 15% 이상 여백, 칸 밖·옆 칸 침범 금지, 실제 투명 배경을 지킨다.
- 긴 소스·로그는 검색 후 필요한 범위만 읽고, 이미 읽은 내용·전체 목록을 반복 출력하지 않는다.
- 빌드는 완료 확인에 1회 실행하고 이후 변경·실패가 있을 때만 재실행한다. 이미지 생성·열기는 필요한 대상만 처리한다.
- 정기 토큰 점검은 매 10번째 작업마다 1회만: 로그 끝 tokens used 상위 10개와 원인 확인·규칙 보완(이번은 141번 특별 점검).


[개발팀장] 판별 테마 패턴 기획 (170) — 코드 수정 금지, 기획만. 창 띄우지 말 것. 토큰 절약.
대표 설명: "맵마다의 패턴이라는 건 예를 들면 정글에서는 원숭이가 나무에 매달려서 코코넛을 가로로 쭉 던진다던지 그런 패턴. 원숭이가 모든 맵에 다 나오는 건 아님."
→ 1~15판마다 그 판 테마(배경·판 이름)에만 나오는 고유 패턴 1~2개를 기획. 각 패턴은 "누가(등장체) / 어디서(맵 위치: 나무·절벽·천장·물 등) / 무엇을(공격·위험 동작) / 어떻게 피하나 / 처음 나오는 판"으로.
조건: 1판은 아주 쉬운 1개만. 판이 올라갈수록 조금씩 어렵게. 같은 패턴 반복 금지(15판은 앞 패턴 조합 가능). 맵 그림에 실제로 있는 지형(나무·바위·물·용암 등) 위에서만. 기존 몬스터(공룡)와 별개의 '판별 등장체'(원숭이 등)는 그 판에서만.
필요한 그림 목록(등장체 동작 프레임·던지는 물건)도 판별로.
